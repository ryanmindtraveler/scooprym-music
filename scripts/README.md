# 管理员工具箱 (Scripts)

`scripts/` 目录是项目的**后台维护工具箱**。

如果说 `src/` 是用户操作的“驾驶舱”，那么这里就是管理员用来日常维系、数据修复和系统排障的“手术刀”。这些脚本通常在命令行中运行，处理那些不需要（或不安全）做成 UI 界面的运维任务。

---

## 🛠️ 脚本分类与用途

### 1. 数据修复类 (Data Repair)
用于在系统更新或发生意外后，确保数据库数据的一致性。
- **`fix-payments.ts`**:
  - **作用**: 自动同步订单状态。如果订单已在 Stripe 完成支付但本地数据库未更新，运行此脚本可批量修正。
  - **命令**: `pnpm fix-payments`
- **`fix-payments-scene.ts`**:
  - **作用**: 批量修复老旧订单的“支付场景”字段，确保财务统计准确。
  - **命令**: `pnpm fix-payments-scene`

### 2. 数据导出与管理 (Data Management)
快速拉取报表或同步外部服务数据。
- **`list-users.ts`**:
  - **作用**: 一键导出所有注册用户的邮箱列表，常用于邮件营销或用户量统计。
  - **命令**: `pnpm list-users`
- **`list-contacts.ts`**:
  - **作用**: 同步检查邮件发送服务 (Resend) 里的联系人名单，方便运营核对订阅情况。
  - **命令**: `pnpm list-contacts`

### 3. 服务探测与调试 (Inspection & Debug)
在不启动前端页面的情况下，直接在后台探测底层服务的连通性。
- **`inspect-auth.ts` / `inspect-auth-minimal.ts`**:
  - **作用**: 检查认证服务 (Better-Auth) 的配置是否正确，快速定位登录失败的原因。
- **`test-auth.mjs`**:
  - **作用**: 运行极简的认证流程测试。

---

## 🚦 如何安全地运行

所有脚本都可以通过 `tsx` 运行，但建议通过 `package.json` 中定义的快捷命令执行。

### 运行准则
1. **环境准备**：脚本会读取根目录下的 `.env` 文件。请确保 `DATABASE_URL` 和相关 API 密钥配置正确。
2. **生产环境谨慎**：带有 `fix-` 前缀的脚本具有**写操作**，建议在生产运行前先在本地备份数据库。
3. **权限要求**：这些脚本只能在具备服务器访问权限的环境中运行。

---

> [!TIP]
> **想添加新工具？**
> 只需要在核心目录新建 `.ts` 文件，并在根目录的 `package.json` -> `"scripts"` 段落中注册对应的别名即可。
