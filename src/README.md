# 源代码核心目录 (Source Code)

`src/` 目录是项目的核心，承载了所有的业务逻辑、UI 组件和后端功能。本项目遵循现代 Next.js 应用的标准架构设计。

---

## 📁 目录结构详述

### 🏗️ 核心架构与路由
- **`app/`**: **Next.js App Router 核心**。包含项目的所有页面路由（Marketing 营销页、Protected 受保护页）以及 API 接口定义。
- **`components/`**: **React 组件库**。
  - `ui/`: 基础原子组件（shadcn/ui）。
  - 各业务模块专用组件（如 `create/`, `dashboard/`, `layout/`）。
- **`actions/`**: **Server Actions 目录**。存放可以直接在客户端调用并在服务器执行的函数，用于处理表单提交、数据变更等。
- **`middleware.ts`**: **中间件配置**。负责处理路由保护（鉴权检查）、多语言重定向等全局拦截逻辑。
- **`routes.ts`**: **路由定义文件**。统一管理项目中的所有路径常量，避免硬编码。

### 🤖 AI 与业务逻辑
- **`ai/`**: **AI 核心模块**。封装了调用不同大模型（OpenRouter, Gemini, DeepSeek）的逻辑，包含文本（歌词）生成和图像设计。
- **`hooks/`**: **自定义 React Hooks**。封装了复用逻辑，如 `useMusicGeneration`（音乐合成管理）、`useCredits`（积分实时通过状态）等。
- **`credits/`**: **积分系统逻辑**。定义积分的计算、发放、消费及结算业务规则。
- **`lib/`**: **底层工具库**。存放通用的工具函数，如日期格式化、加密、API 请求封装等。

### 💾 数据与存储
- **`db/`**: **数据库层**。包含 Drizzle ORM 的表结构定义 (Schema)、关系定义以及数据库迁移历史。
- **`storage/`**: **云存储集成**。封装了对 Cloudflare R2 或 S3 的文件读写操作。
- **`stores/`** & **`store/`**: **状态管理**。使用 Zustand 定义的全局状态（如音乐播放器状态、全局加载状态等）。

### 🌍 国际化与通信
- **`i18n/`**: **多语言配置**。管理国际化路由策略及 `next-intl` 的中间件配置。
- **`mail/`**: **邮件系统**。存放邮件发送逻辑及 React-Email 编写的邮件模板。
- **`newsletter/`**: **新闻通讯模块**。处理用户订阅邮件列表的相关逻辑。
- **`notification/`**: **通知系统**。处理应用内通知或推送服务的集成。

### 💳 支付与转化
- **`payment/`**: **支付核心模块**。处理 Stripe Webhooks、订单验证及订阅状态维护。
- **`analytics/`**: **数据分析集成**。封装了 PostHog、Google Analytics 等埋点和统计逻辑。

### 🎨 样式与静态资源
- **`styles/`**: **全局 CSS 样式**。包含全局样式定义、字体导入以及 Tailwind CSS 4.0 配置。
- **`assets/`**: **内置静态素材**。通常存放需要在代码中 import 的图片或字体（不同于 `public/`，这里的资源会参与构建）。
- **`types/`**: **全局类型定义**。统一存放项目中通用的 TypeScript 接口和类型声明。

---

## 💡 开发提示
1. **不要跨层调用**：尽量保持逻辑解耦，UI 组件只负责展示，复杂的业务逻辑应放在 `hooks` 或 `lib` 中。
2. **优先使用 Server Actions**：对于简单的数据交互，优先考虑在 `actions` 中实现，而不是创建新的 API 路由。
3. **类型安全**：所有新功能应在 `types/` 或就近定义完善的 TypeScript 类型。
