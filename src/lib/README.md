# 共享模块目录

`src/lib` 按业务职责组织跨页面、API 和后台任务共用的代码。新增文件优先放入对应目录，测试与实现放在一起。

| 目录 | 职责 |
| --- | --- |
| `auth/` | 认证配置、客户端、会话、安全操作、验证码与会员访问检查 |
| `creation/` | 创作流程、任务投递、阶段恢复、音频检查点、重试与成品检查 |
| `songs/` | 歌曲状态、来源、编辑信息、发布兼容、SEO、评论与互动 |
| `stories/` | 新闻投稿、投票、选题编排与每日热榜归档 |
| `story-radar/` | 新闻采集、分类评分、候选类型及已生成歌曲查询 |
| `music/` | 音乐风格、制作配方、歌词结构与生成错误分类 |
| `infrastructure/` | 队列服务、限流、日志与流式响应缓存 |
| `shared/` | 跨业务日期与格式化、引用组合、共享常量和演示模式 |
| `seo/` | 页面元数据与多语言替代链接 |
| `urls/` | URL 构造与公开页面语言路由规则 |
| `docs/` | 文档国际化及 Fumadocs 内容源（含博客、作者等内容集合） |
| `utils.ts` | 通用类名合并与字符串工具，保留组件生成器约定的路径 |

## 业务流程与边界

新闻由 `story-radar` 采集或经 `stories` 投稿，经过选题、投票后交给 `creation`。创作流程调用 `src/ai` 中的模型实现，完成歌词、音乐、封面和成品检查；`songs` 提供发布相关规则、展示与互动能力。`infrastructure` 提供底层服务。

- 页面和 API 仍放在 `src/app`；数据库、支付、积分和存储由各自的现有模块负责。
- `music` 管理音乐领域规则；`creation` 管理跨步骤流程与任务生命周期。
- `story-radar` 管理新闻发现；`stories` 管理投稿、选题及每日榜单。
- 仅真正跨业务复用的辅助能力放入 `shared`，领域规则放回所属业务目录。

## 引用约定

- 跨目录使用明确的别名路径，例如 `@/lib/auth/auth-client`、`@/lib/creation/song-workflow`。
- 同目录可使用相对路径；测试文件沿用 `*.test.ts`，与被测实现同目录。
- 不新增统一导出所有模块的入口，避免客户端间接引入数据库、密钥或服务端依赖。
- 客户端只导入适用于浏览器的模块；服务端模块保留原有的运行环境约束。
- 目录调整时同步更新静态导入、动态导入、测试模拟、脚本和文档中的路径。
