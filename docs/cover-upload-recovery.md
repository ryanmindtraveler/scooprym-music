# 封面上传恢复

## 业务流程与边界

音乐已保存后，封面失败只能恢复封面，不能再次调用音乐模型。自动制作与手动封面重试统一调用 `prepareCoverAsset`。

1. 按歌曲、歌词、来源正文、美术提示和原封面标识计算恢复点 ID。
2. 原子领取 6 分钟租约，阻止相同输入并发生成。
3. 模型结果立即写入专用表；远程图片下载后保存为 data URL，避免原地址过期。
4. 上传使用恢复点派生的固定对象 key，失败重试写回同一对象。封面上传每次最多 20 秒，最多 3 次；模型和下载共用 220 秒预算。
5. 成功后清除图片大字段、保存 URL、key 和尺寸。歌曲最终写库失败时可直接恢复该结果。
6. 完成或失败均释放租约；进程异常退出由租约到期恢复。删除歌曲时级联删除恢复记录。

恢复点不属于公开歌曲字段或工作流步骤元数据，客户端不会全量加载图片正文。未成功上传的图片保留至恢复完成或歌曲被删除。

## 存储错误诊断

上传失败保留安全的底层错误码，例如 `UND_ERR_CONNECT_TIMEOUT`、`ECONNRESET`，帮助区分连接超时和断连；不输出底层错误中的签名地址。原历史记录只有 `fetch failed`，不足以确定当时具体网络故障。

## 验证与部署

- 迁移：`0038_cover_asset_checkpoint.sql`，当前连接数据库已应用。
- 数据库集成测试：`RUN_DATABASE_TESTS=1 pnpm exec vitest run src/lib/creation/cover-asset.integration.test.ts`。真实 PostgreSQL、模拟模型和存储，事务主动回滚。
- 覆盖上传失败后恢复同一字节及 key、已上传结果复用、并发生成互斥、明确替换封面建立新恢复点。
- 发布到其他环境前先应用迁移，再发布代码。

旧版本未持久化的封面字节无法追溯恢复，需要重新生成一次封面；已保存音频不受影响。
