## 4. 业务流程、架构与边界

目标浏览流程：六专题汇总 → 对应专题的原主题／歌曲 → 页内试听或独立 `/songs/{UUID}` 详情。Gallery 与 Internet Lore 共享公开、播放和详情门禁，发布栏目只控制展示入口。未发布时仍只展示旧页已有歌名，不输出私人音频、歌词或失效详情链接。专题歌曲排除 Gallery、首页 Today／推荐及全部榜单，独立公开详情和 sitemap 不因栏目排除而隐藏。

本轮完善后的阅读流程：汇总页进入原专题 → 阅读原创作主题与对应原歌名 → 通过可展开索引跳转到本页条目 → 阅读专题介绍与其他五专题。没有原歌曲绑定的五类不再显示空歌单大框，改为展示旧主题。所有主题描述说明戏仿创作角度，不把旧稿中的无来源细节或年份当成核实新闻。

- `topics.ts` 保存用户确认的六分类、介绍和解读角度，删除此次新增的六首示例绑定。
- `song-catalog.ts` 保存从旧源码确认的稳定歌曲 ID、旧顺序及历史名称；禁止运行时关键词匹配，也不按同名替换版本。
- `archive-cases.ts` 保存六类原九主题及来源标题，合计 54 项；新增的 premise 是编辑补充的喜剧解读，和原稿历史事实区分。只为旧源码明确关联的九项保留 songId。
- `queries.ts` 通过明确的 `publication_channel=internet_lore` 与 `lore_topic_slug` 查询实际公开作品，保留有效音频、最新生成未失败等公开条件；原九首优先按旧顺序展示，不按关键词、同名或相近内容推断归属。历史 ID 白名单继续作为原歌恢复与顺序证据，新增作品只能由管理员明确指定专题。
- 歌单组件展示原列表；公开记录不存在时显示 `Archived · Currently unavailable`，不读取私人音频、歌词或创作数据。
- `InternetLoreArchive` 用主题标题、创作角度及紧随其后的原歌状态构成条目，移除重复唱片占位；原生 details 索引支持键盘，九个锚点可抓取，桌面双列、手机单列。
- 汇总页显示每类九个原主题，歌曲数以明确归属且实际可公开的作品计算；不把主题数当歌曲数。专题入口使用旧专题已有配图，不展示歌曲封面或借用当前作品封面。
- 弗吉尼亚浣熊和 Swish 两篇新编案例不再作为原歌单或内页作品依据，源码暂时保留，不混入历史歌曲关联。
- 七个新版路由、导航及 sitemap 保留；未知专题 404，旧功能页继续 410。顶部 Send a Story 删除，首页投稿模块与页脚入口保留。

最新栏目实现已定向新增数据库字段，并通过后台保存一首原歌的栏目归属；没有改原歌词、音频或封面，没有正式公开九首。迁移默认将既有作品归入 Gallery，268 首原公开状态未变。此次只执行 0045，不运行其他待迁移，也不推进 Drizzle 游标；正式发布按下一节的顺序执行。
