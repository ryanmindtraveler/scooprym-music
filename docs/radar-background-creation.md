# 热点雷达后台创作

点击热点雷达的创作歌曲按钮，调用管理员专用 `/api/admin/story-radar/:id/generate`，返回202和任务ID，不跳转页面。不同热点可连续点击；同一热点由数据库主键、固定workflowRunId/songId及队列去重保护。页面每10秒读取状态，离开页面不取消任务。

## 执行边界

- 使用现有风格推荐、歌词双稿/编辑/安全检查与音乐提交服务，不创建另一套歌词提示词。
- 歌词各检查点持久化后投递下一步，后续步骤复用原文快照和已完成检查点；歌词完成后自动提交音乐，不等待人工赞成。
- 歌词队列并发2；音乐生产队列并发2。音频、封面、上传继续复用既有worker和重试策略。生成完成不自动发布。
- 失败任务可从雷达重试，固定任务ID不变。已移交音乐阶段的失败从创作台原有队列恢复，不新建歌曲。
- 外部模型响应丢失、单个歌词步骤超过平台时限等情况下，不承诺上游模型调用绝对仅一次；已落库检查点及音频继续复用。

## 上线前

1. 审核并应用迁移0034（同时保留前一轮0033归档迁移），不要直接对未知状态生产库运行全部迁移。
2. 配置QSTASH_TOKEN、QSTASH_CURRENT_SIGNING_KEY、QSTASH_NEXT_SIGNING_KEY与可公开访问的NEXT_PUBLIC_BASE_URL；签名worker路径须能被QStash访问。未配置时拒绝入队，不使用浏览器或after()长请求代替持久队列。
3. 本地localhost不能被QStash访问，需配置隧道或在可访问部署测试。
4. 确认队列套餐支持flow-control与所需请求时长。每个歌词检查点仍需在函数300秒内完成；超时后由队列重投并复用已保存结果。
5. 未执行真实付费批量测试、数据库迁移或生产部署，不视为线上验收完成。

当前历史投票结果区域的“打开创作台”入口仍保留原人工创作行为；本轮修改范围是热点雷达列表。
