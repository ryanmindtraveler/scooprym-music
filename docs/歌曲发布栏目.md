# 歌曲发布栏目

最近更新：2026-10-14 10:23。

公开状态和发布栏目是两个独立设置。`isPublished` 决定能否公开访问，栏目决定在哪里展示；同一首歌只属于 Gallery 或 Internet Lore 之一，两类已发布歌曲都保留规范 `/songs/{slug}` 详情、试听、分享和现有互动，并允许搜索引擎收录。链接使用既有公共路径生成器，不手拼 UUID；切换栏目不生成第二个详情地址，也不自动发布或下架。

## 展示规则

| 入口 | Gallery | Internet Lore |
| --- | --- | --- |
| Gallery、首页 Today／推荐、全部榜单 | 按既有规则展示 | 排除 |
| 所选 Internet Lore 专题 | 不按关键词自动归入 | 页内试听与详情入口 |
| 独立歌曲详情、公开互动、sitemap | 已发布时保留 | 已发布时保留 |
| 未发布作品的音频、歌词、详情 | 不公开 | 不公开 |

专题入口沿用专题配图，不展示歌曲封面。原歌名称和对应原创作主题保留，主题数与歌曲数分别统计。其他五类缺失的原歌关联不得用当前曲库或相似歌名补位。

## 后台操作

1. 在后台歌曲列表打开该歌曲的发布栏目设置。
2. 选择 `Gallery`，或选择 `Internet Lore` 并指定一个专题。
3. 保存栏目。公开状态仍由原发布开关独立管理。
4. 发布时继续通过管理员认证、成品状态、有效音频和既有工作流门禁；更换栏目也使用事务服务，失败保留编辑内容。

固定六专题为 `absurd-social-phenomena`、`entertainment-topics`、`gossip-roast`、`news-parody`、`meme-culture`、`comedy-drill`。数据库字段 `publication_channel` 默认 `gallery`；Gallery 的 `lore_topic_slug` 必须为空，Internet Lore 必须为上述六值之一，应用及数据库都执行校验。

## 九首原歌的发布顺序

用户已授权将 `src/lib/internet-lore/song-catalog.ts` 中已确认的九首原歌发布到 `Internet Lore / absurd-social-phenomena`，使用原 ID、音频、歌词和封面，不替换同名版本。其他五专题原歌绑定仍未找到。

本地与线上共用数据库，必须按以下顺序完成：

1. 单独应用 `src/db/migrations/0045_song_publication_channel.sql`。只执行 0045，不运行全部待迁移，不推进 Drizzle 迁移游标；既有公开状态保持原值。
2. 完成新代码构建、上线，并验证线上 `/api/public/gallery` 返回 `publicationChannelsVersion=1`。
3. 运行 `scripts/publish-original-lore-songs.ts` 的默认预检：事务内核对九个原 ID、排期及内容哈希，设置栏目并验证发布门禁，最后回滚。预检报告不能当作发布成功。
4. 线上版本检查通过后，按九个明确原 ID 在真实管理员后台逐首核对栏目及专题，然后点击发布；后台动作刷新公共缓存及 sitemap。本次正式恢复采用该路径，未使用 CLI 直接 SQL 绕过后台。脚本的 `--apply` 仅保留为受版本检查保护的定向工具，不能把默认回滚预检当成正式发布完成。
5. 验证九首在荒诞社会现象页能播放，九个独立详情返回 200 且规范地址和 sitemap 正确；同时验证 Gallery、首页 Today／推荐及所有榜单均不含这九首。核对原音频、歌词、封面哈希未变。

脚本只处理确认的九个 ID，提交前保存状态备份；排期被改动、作品哈希变化、公开栏目冲突或任一门禁失败都会停止事务。审计报告保存于 `F:/CodexHome/audits/lore-publication-2026-10-14/`，不在文档中公开音频地址、凭据或私人创作数据。

## 版本回退边界

源码发布分支尚未合并 master，主工作区仍为 master 且原未提交修改保留。后续上线必须包含本轮栏目逻辑，避免旧代码覆盖正式新版。
