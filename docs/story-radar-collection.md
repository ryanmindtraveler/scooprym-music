# 热点雷达采集与排查

## 业务流程与边界

新闻源读取 → URL 规范化与去重 → 标题和摘要辅助分类 → 完整保存有效报道 → 后台审核与近似转载分组 → 首页投票及每日归档。

- `src/lib/story-radar` 负责来源适配、分类、扫描记录和新闻库存；`src/lib/stories` 负责人工精选、投票和日报规则。
- 未命中关键词的报道仍保存，分数为 0、匹配词为空，后台显示待审和建议分类。来源默认分类只是提示，不作为自动精选依据。
- 首页自动候选只允许有匹配词、有分数、发布时间在最近 7 天内的新闻；初次自动补充精选限制为最近 72 小时。人工精选保留编辑优先权。
- 已经精选、忽略或采纳的状态以及歌曲关联，不被重复采集覆盖。
- 近似转载按标题、来源、48 小时时间距离保守分组，保留全部原始记录和链接；取消分组可逐条操作。它不是语义级事件聚类，可能漏合并不同写法的同一事件。
- 后台每页 100 条，可翻页访问全部库存；搜索、状态和待审筛选作用于当前页。

## 采集计划

### Google Trends

- 默认启用美国区 Trending now RSS（无需 API 密钥）。`STORY_RADAR_GOOGLE_TRENDS_ENABLED=false` 可关闭，`STORY_RADAR_GOOGLE_TRENDS_GEO` 可改为其他受支持的两位国家代码。
- 同时采集多个地区时配置 `STORY_RADAR_GOOGLE_TRENDS_REGIONS=US,GB,HK,TW`，优先于旧的 GEO；最多 8 个，自动去重。默认仍沿用 US，不自动改变现有地区选择。每个地区单独显示渠道健康，上游不支持或拒绝某地区时保留失败报告，不影响其他地区。地区可用性以实际 RSS 响应为准。
- 使用独立适配器读取 `ht:news_item` 关联媒体新闻，顶层热搜词和 Google 搜索链接不会当作新闻入库。每个报道保留热搜词、地区、原始估算搜索量、热搜开始时间和本次观测时间。
- 0036 迁移新增候选表 `trend_signals` JSON 字段；后台报道卡展示这些线索，搜索框支持查找热搜词。历史线索附带观测时间，不承诺一直处于实时热榜。
- 同一 URL 跨媒体订阅与 Trends 合并，优先使用原始媒体的标题、分类和日期；重复扫描更新线索，不新增重复报道，不覆盖人工处理状态。
- Trends 的 RSS 日期属于热搜，不能视作报道发表日期。只有 Trends 提供的报道保持 `publishedAt=null`，不会据此自动进入首页；编辑可人工精选。
- Google Trends RSS 是当前热点的有限快照，不代表所有 Google 搜索趋势或完整历史。官方导出说明见 [Google Trends 帮助](https://support.google.com/trends/answer/3076011?hl=en)。

`/api/cron/story-radar` 每 12 小时补充库存，不生成音乐。日报仍在洛杉矶 18 点出刊，优先使用最近一小时的可用扫描；没有可用记录时补抓。音乐定时发布维持原计划。

部署前执行 `pnpm db:migrate`，并配置 `CRON_SECRET`。0035 新增扫描记录表和运行中扫描的部分唯一索引。0033 兼容已经手工建好日报表的环境；本次本地已核对现有表结构并完成迁移。

生产项目保留 Vercel Hobby，仅将每日任务留在 `vercel.json`。2026-09-10 起由现有 QStash 每 12 小时签名 POST 此接口，校验有效期、正文和目标地址；GET 仍保留 `CRON_SECRET` 校验。首次上线后须单独同步调度，步骤见 [Hobby 调度说明](./hobby-scheduling.md)。参考 [Vercel Cron 定价与限制](https://vercel.com/docs/cron-jobs/usage-and-pricing)。

本地 `pnpm dev` 不会自动执行 Vercel Cron，使用后台扫描按钮验证。代码尚未部署时，线上采集频率不会发生变化。

## 渠道健康状态

后台显示最近一次扫描的各源状态、接收/有效数量、待审量、旧闻量、最新文章日期及错误。新增数仅统计真正插入的 URL，已存在 URL 另记为刷新数；跨源相同 URL 会汇总去重，因此渠道有效数之和可能大于总有效数。

- `completed`：启用的来源均正常完成，包括正常空订阅。
- `partial`：部分来源失败，其他结果已保存。
- `failed`：全部启用来源失败，或保存失败；接口返回失败状态，不显示扫描成功。
- `running`：正在采集；超过 10 分钟的扫描视为异常，下一次采集可接管。
- `disabled`：渠道未启用，例如 `STORY_RADAR_GDELT_ENABLED` 不为 `true`。

RSS 请求超时覆盖响应体，网络错误、429 和 5xx 有有限重试；403 等明确拒绝不会反复请求。每个响应限制 2 MB。GDELT 仍受上游每次最多 250 条和 48 小时查询范围限制；其日期来自上游 `seendate`，不是独立核实的原文发表日期。

## 本地实测（2026-09-07）

通过已登录 Google 账户的 Chrome 后台连续运行两次扫描：首次新增 101、刷新 19、有效 120；第二次新增 0、刷新 120。数据库库存由 61 增至 162。结果显示 TMZ 返回 HTTP 403，其余 6 个 RSS 正常；Oddity Central 最新日期为 9 月 1 日，10 条均标记为超过 3 天；GDELT 按本地配置显示关闭。

上述结果只代表本机网络与当时订阅内容。保留有效报道不等于保证渠道历史新闻全部抓齐；源自身只提供有限滚动窗口，停机期间仍可能漏掉窗口外文章。
